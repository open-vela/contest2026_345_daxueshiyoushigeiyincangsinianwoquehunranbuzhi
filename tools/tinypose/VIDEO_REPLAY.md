# 原v4c与仅SC＋光照：视频对照

当前状态：用户确认视频尚未录制。工具已完成原生算法单元测试和合成AVI端到端检查，尚无真实人物视频对照结果，不据此判断两个模型的实际计数优劣。

## 采集最小一批素材

先录3段固定机位视频：正常光、偏暗、偏亮各一段，每段5–10个完整深蹲。条件允许再加入另一位参与者及一段空画面/走动不深蹲的负例。用手机即可先做候选筛选，最终仍需SC2336真机验证。

每段开始至少站直2秒，让状态机学习站立基线；结束后站直2秒，不要在最后一次起身中途停止录像。尽量30fps，原始速度、不剪切拼接、不使用美颜滤镜，摄像头固定。全身尤其肩、髋、膝、踝保持可见，人体居中，避免镜头移动或自动跟踪。建议竖拍，固定斜前方视角；侧身让两条腿完全重叠会增加遮挡。光线组间尽量保持相同机位、距离、服装和动作节奏。

手机素材和板端的摄像头视角、RAW10转换、曝光不相同，因此手机测试不能证明SC2336域的收益。背景、服装和遮挡困难样本可以保留，但标注实际条件，避免将所有困难帧筛掉。

推荐存放位置：`.secrets/datasets/personal-video-eval-v1/videos/`。这些视频优先作为评估保留，先不混入训练；如果之后用于训练，不能继续当作独立盲测。

## 视频清单与人工事件

复制 `video-replay.example.json` 到私有评估目录并填写。视频路径相对清单所在目录；与已有导入器一致，需要人物ID、来源、许可、单人确认、split。对本批建议用holdout，同一人物/视频不能跨split。深蹲用exercise=squat，空画面或走动负例用negative。

- `rotation` 是解码后的额外顺时针旋转，默认0；手机文件解码后已经朝上时保留0。
- `start_sec`、`end_sec` 使用原视频秒数，区间右端不包含；end_sec=null表示解码至结尾。
- `warmup_sec` 默认2，这段只学习站立基线；进入评估时重置计数并保留基线。
- `expected_reps` 未核对时为null。仅有总次数可计算净计数误差，不能分别计算漏计、多计。
- `events_reviewed=false` 时，即使有候选事件，也不作为人工真值；缺标注指标输出null。

逐帧查看原视频，以“起身回到该次动作完成位置”的时刻填写complete_sec；可同时填蹲底时刻bottom_sec和开始下蹲时刻start_sec。例如：

```json
{
  "expected_reps": 2,
  "events_reviewed": true,
  "events": [
    {"start_sec": 3.0, "bottom_sec": 3.8, "complete_sec": 4.7},
    {"start_sec": 6.0, "bottom_sec": 6.8, "complete_sec": 7.7}
  ]
}
```

示例时间只是格式说明，不能直接用于实际录像。events必须按完成时刻排序，全部位于warmup之后的评估区间；reviewed=true要求事件数与expected_reps一致。零动作负例应明确填写expected_reps=0、events=[]、events_reviewed=true。

## 执行

在团队仓库根目录执行，无须GPU；依赖现有GPU虚拟环境中的TensorFlow、OpenCV、Pillow、NumPy及本机C编译器：

```bash
CUDA_VISIBLE_DEVICES=-1 .secrets/tinypose-gpu-venv/bin/python \
  tools/tinypose/video_replay.py \
  --clips .secrets/datasets/personal-video-eval-v1/clips.json \
  --output .secrets/experiments/video-replay-v1 \
  --fps 10 --match-window-sec 1
```

输出目录必须不存在，且位于仓库.secrets内。模型SHA固定为原v4c和第二轮sc_only_photo，避免误用候选。相同解码帧先转192×192等比例黑边图，随后使用原板端C预处理函数完成2×2面积缩小和各模型INT8量化。手机图像生成RGB192的方式不等同于传感器捕获链路。

两个模型交替推理同一帧，不按模型运行速度跳帧；帧采样上限10fps不代表板端实测吞吐。使用TFLite BUILTIN_REF核，主机推理时间仅作诊断，不是P4性能数据。解码时间戳优先，失效时使用frame_index/FPS并记录，VFR回退时不能声称精确时钟。单次采样间隔给事件时刻带来时间分辨率限制，默认约0.1秒或受原视频帧率限制。

## 输出和指标口径

`comparison.json` 含每段与汇总指标、模型/视频/源码/清单哈希；`clips-source.json` 保存输入清单快照。`clip-NNN-frames.jsonl` 保存每帧时间、8点坐标置信度、膝角、站立基线、状态和计数事件。运行中失败不会生成成功汇总，不覆盖旧结果。

复用 `squat_fsm.c` 的自适应计数分支，与SC2336探针中的TinyPose动作计数一致；不模拟产品会话、BODY_CHECK稳定门槛、队列或屏幕，也不额外增加One-Euro滤波。预热阶段学习基线，开始评估时调用原begin_capture接口。

- **漏计/多计**：预测事件与人工complete_sec按时间顺序一对一匹配，最大化匹配数量，再最小化绝对时间差。默认±1秒窗口，两个模型使用相同预先指定窗口，窗口之外分别算漏计/多计。总数相同仍可能两者同时存在。
- **计数延迟**：匹配事件的预测计数时间减人工完成时刻，保留正负值；负值表示提前触发。输出中位数、P95和平均绝对时间差，逐次保留bottom_to_count_sec。当前原生状态机在起身恢复时完成一次计数，不在第一次蹲底时加一；蹲底到计数包含动作本身的起身过程。
- **连续有效率**：严格口径为全部8点置信度≥0.3；实际计数准入口径为至少6点≥0.3且全部8点≥0.2。两种均记录有效帧占比、最长连续有效帧数/时间跨度、有效转无效次数和超过1秒的采样间隙。有效表示通过置信度门槛，不代表坐标经过人工验证。
- **净计数误差**：预测次数减人工总数；没有逐次人工事件时只报告这项和连续性，不虚构漏计、多计、延迟。

离线事件时差不包含摄像头采集、板端推理耗时、异步队列及LCD刷新，无法直接解释用户感知的全部“慢半拍”。后续板端需要分别记录采集时间、推理完成时间和显示更新时间。
